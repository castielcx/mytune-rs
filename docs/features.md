# MyTune 2

Windows gaming-tuning app: a clean-room rebuild of HyperTune 2.7.1.96 (CompReady) features with a nicer UI.

**The C# app is gone (2026-11-19, user's choice "Everything C#", told it was in no git repository and permanent).** Deleted: the C# source (`Views`, `Services`, `Tweaks`, `MyTune.csproj`, ...), `installer\` (C# setup script, `redist\` driver installers, `release.config.json`, built setups), `publish*`, `bin`, `obj`, `_disabled`, and the installed MyTune 2.3.2 (`C:\Program Files\MyTune`, shortcuts, uninstall key; removed by hand, because its uninstaller kills every `MyTune.exe`, deletes the autostart task and can delete `%ProgramData%\MyTune`). Only `mytune-rs\` (the Rust app, the only MyTune now), `.claude\`, `.claude-flow\` and this file remain. Everything below about the C# app, its files and its installer is history: those paths no longer exist, `data/catalog.json` can no longer be regenerated from C#, and unported features (Game Hub, Profiles, the other PC checks, updater install, GPU overclock) have no C# reference left. The C# setup's Inno `AppId` was `{B7E3C1A4-5D2F-4E8A-9C61-3F0A7D5E2B19}`. `.claude\commands\release.md` still describes the C# release.

## Decisions
- Connection health (Network page, between Speed test and Tweaks, added 2026-11-21): a read-only Check button in `crates/mytune-core/src/connhealth.rs` and `health_ui` in `crates/mytune-ui/src/internet.rs`. One run on its own thread, nothing stored. Targets the physical adapter with the lowest-metric default route. Checks: 50 ICMP echoes to the router (`IcmpSendEcho`), adapter errors and discards, Ethernet link speed against `*SpeedDuplex`, Wi-Fi signal, band and crowded channel (Native WiFi, Windows' last scan). No localized text is parsed. Measured on this PC (I225-V): 0 of 50 lost in both runs, median under 1 ms, p95 under 1 ms and 11 ms, 0 bad of 6.87 million packets, 1 Gbps on a 2.5 Gbps card = Info. Never tried on screen or on a live connection: the Wi-Fi checks, including the location-denied path (this PC runs on Ethernet). Vendor `*SpeedDuplex` codes other than Intel's Mbit/s values are ignored.
- Wi-Fi latency tuning (`net.wifi`, Network page, added 2026-11-21): an `AdapterPropertyTweak` that sets `RoamingPreferredBandType` = 4 (prefer 5 + 6 GHz) and `RoamAggressiveness` = 0 (lowest). Keywords and values read from the Intel AX211 driver 23.150.0.4 (defaults 0 and 2). A driver without the keyword or value is left alone. Never applied on a real connection and ping was not measured: this PC runs on Ethernet. Non-Intel drivers were not checked. Since the 2026-11-21 audit every adapter and binding backup also stores `guid:<adapter>` = `InterfaceGuid`, so a renamed adapter is found and a removed one is skipped; an old name-only backup fails with a clear message while another unknown adapter still holds the tweak's value. A backup with no originals is "nothing to undo" and writes no driver defaults. These PowerShell write paths were checked with fakes only.
- Larger adapter buffers (`net.buffers`) removed on 2026-11-21: the Intel I225-V driver 2.1.5.4 publishes no default or limit for `*ReceiveBuffers`/`*TransmitBuffers`, so no safe target exists and the switch only failed. Do not write a guessed value. The tweak object stays so "Revert all" restores existing backups.
- Take ownership (`qol.takeown`, `special.rs`), 2026-11-21: the right-click verb `MyTuneTakeOwn` starts the exe with `--take-own "%1"`, so the manifest brings the UAC prompt and no shell parses the file name. Owner and full access go to Administrators by SID. Folders are walked item by item (`take_own_walk`), never with icacls `/t`, which follows junctions out of the folder: a reparse point gets icacls `/l` on itself and is not entered. Drive roots, Program Files, ProgramData, Users, profile roots and any folder at or under Windows are refused, also through a junction in the path; a single file under Windows stays allowed. If the real location cannot be read, nothing changes. Each item starts two programs and logs both, so a huge folder is slow. Off also deletes the old `MyTuneTakeOwnership` keys. Not yet tried with UAC on or on German Windows.
- Adapter and binding tweaks, 2026-11-21: a stored backup with no entries now acts as no backup, so one Off writes the driver defaults through the strict read; a failure keeps the entry. Undo with an adapter unplugged restores the others and keeps the backup; only then Restore offers Forget, which tries the revert once more first. The old `net.dns` revert follows the same rule. `adv.classicmenu` without a backup deletes its own CLSID key tree.
- Stack: .NET 8 WPF (`net8.0-windows`, win-x64, framework-dependent), requires admin (app.manifest). Build: `dotnet publish -c Release -o publish -p:PublishSingleFile=true` → `publish\MyTune.exe`.
- UI: blocky look since 2.4.2 (user choice, reference image of orange/red colour blocks): everything square (no CornerRadius, no ellipses except the controller stick ring), sidebar and title bar painted with the accent (default orange `#FF5A0A`, 8 presets in `Services/Accent.cs`, old default `#60CDFF` maps to orange), warm near-black content (`#130C09` layer, `#1D130F` cards with a 3 px `AccentDark` left edge), fixed block shades `BlockRed/Crimson/Maroon/Amber/Orange` + `Ink` for decoration (Home hero, colour strip over every page, grid node), mono font for labels, own styles in `Themes/Fluent.xaml` (no UI library). Pick lists are a `DropButton` field with a popup of `RowButton` rows (Display page: resolution and refresh rate with one Apply). Since 2.4.0 the sidebar is grouped by what the user wants to do (it scrolls when the window is short): Home; GAMING: Optimize (General/Advanced/Network), Game Hub, Internet; DEVICES: Mouse, Display, Controller; WINDOWS: Debloat, Customize, Tools; CHECK AND UNDO: Diagnostics, Restore; Settings at the bottom. Page keys in code are unchanged (`dashboard` = Home, `vpn` = Internet). Every nav item has a plain-language tooltip; Ctrl+F focuses the search.
- Home (`Views/DashboardPage.xaml`, `DashboardVM`) is written for people who don't know PCs: a status card that counts only the recommended optimizations (`FirstRunWindow.OptimizationSet`, skipping unavailable and update-locked ones) with "Optimize now" (lists the tweaks and asks before applying), the live tiles, the PC check, three shortcuts and "This PC". The PC check lives on Home, not Tools; Profiles live in Settings > Backup.
- PC check also reports Resizable BAR (NVIDIA RTX 30+, read from nvidia-smi BAR1 vs video memory; tip only, it is a BIOS switch), Game Mode off (fix turns it on), mouse acceleration on (tip only, the switch is on the Mouse page) and a laptop running on battery. These are checks, not tweaks.
- Libraries: LibreHardwareMonitorLib 0.9.6 (uses the PawnIO driver for CPU temps; user installed PawnIO via winget), NvAPIWrapper.Net for NVIDIA DRS profiles, Vortice.Direct3D11 + Vortice.D3DCompiler 3.8.3 (MIT; Direct3D 11 compute for the GPU benchmark, no driver needed).
- HidHide (hiding the real controller) and Interception (mouse angle snap) were removed on purpose; don't re-add features that need drivers Setup doesn't ship.
- GPU overclock (added on request 2026-11-02): manual NVIDIA core/memory offsets and power limit in Settings > Game booster (`Services/GpuOverclock.cs`, NVAPI pstates20 + power policies), applied only while a Game Hub game runs and reset after (`GameBooster.SetOverclock`; `State.GpuOcActive` resets it after a crash). Sliders cap core ±300, memory -500..+1500 MHz. No CPU overclock, no auto scan.
- No in-game overlay in HyperTune; a crosshair overlay was added to the Rust app on request 2026-11-20 (see the Crosshair bullet). No auto CPU/GPU overclocking, accounts, telemetry or winget installer — user chose to leave these out. A benchmark was left out first, then added on request (2026-11-01): Diagnostics > Benchmark (`Services/Benchmark.cs` CPU + RAM, `Services/GpuBench.cs` GPU, runs saved in `state.json` under `Benchmarks`); it scores only, no stress test. Each score gets a Low/Fair/Good/Great rating from rough limits in `Services/BenchRating.cs` (estimated from typical hardware, not measured on a database of PCs).
- Autostart (opt-in toggle in Settings): HKCU Run entry "MyTune" (visible/disableable in Task Manager > Startup apps) runs `schtasks /run /tn MyTune`; that on-demand Task Scheduler task has highest run level (no UAC prompt; elevated apps in a Run key are skipped by Windows) and launches `MyTune.exe --minimized` (hidden in tray). Code: `Services/Autostart.cs`.
- Every tweak backs up originals to `%ProgramData%\MyTune\state.json` before changing anything; revert restores them. Without a backup, revert changes nothing (Rust port since 2026-11-15: registry catalog tweaks without a backup write their catalog `default` instead, null deletes the value, so off is the opposite of on; tweaks with unknown defaults still change nothing and the UI says so). A revert that fails (any value not restored) throws and keeps the backup for another try. Tweaks stay applied until reverted (not reverted on exit). A restore point is created before the first change. Log: `%ProgramData%\MyTune\mytune.log`.
- `state.json` is flushed to disk on every save and the previous version is kept as `state.json.bak` (`File.Replace`); if `state.json` is not valid JSON, Load uses the `.bak` (a bad file is kept as `.corrupt-*`). If it only cannot be read right now (locked, no access), it is left alone, the `.bak` is not used, and apply, revert and saves refuse until it can be read; the same when both `state.json` and `.bak` are invalid. Saves are serialized across processes by `state.json.lock`. Before the first load the elevated app closes `%ProgramData%\MyTune` to non-admins (`store::harden_dir`: SYSTEM and Administrators full, Users read and run, owner Administrators; links planted there are removed, WebView2's network-sandbox grants stay, `acl-done` marks a complete pass). Apply and revert first re-read the file, so a second MyTune cannot capture tweaked values as originals.
- Data folder trust (2026-11-21): a non-admin can set `HKCU\Environment`, which an elevated process inherits, so every ProgramData path comes from `util::program_data()`, never from the environment: HKLM `ProfileList\ProgramData` read raw, a leading `%SystemDrive%` replaced by the drive of `windows_dir()`, and `<windows drive>\ProgramData` if the value is missing or still holds a `%`. `FOLDERID_ProgramData` and `FOLDERID_UserProfiles` must not be used: the shell expands their `%SystemDrive%` from the process environment. `MYTUNE_DIR` works only for an exe in a `deps` folder (where cargo puts test binaries in every profile) that is not named `MyTune` (`util::honors_test_dir`). `mytune-chat` now depends on `mytune-core` for this. System paths likewise: `util::windows_dir()` (`GetSystemWindowsDirectoryW`, literal `C:\Windows` if that fails) feeds `system32()`, diagnostics, stability, disk use and the Cleaner; VPN CLIs use `FOLDERID_ProgramFiles`. The take-ownership guard reads only machine data (`take_own_trusted`; the Users folder from HKLM `ProfilesDirectory`). The autostart task XML is written beside the exe, not to TEMP. Cleaner: only the exact roots Windows `Temp` and `Prefetch` are cleaned as admin, entry by entry, never through a link, with the root held open without write or delete sharing and skipped if it is a link. A spec equal to the temp folder is never a machine target. Every other spec, the WER folders included (Authenticated Users can write and delete on those roots), is deleted under `util::as_standard_user`: a short-lived thread impersonating a standard-user token (Administrators and S-1-5-114 deny-only, no privileges, Medium integrity), skipped if that token cannot be made, never retried as admin. Clean Start's `start2.bin` and every game settings file use the same helper (`util::as_user`): the file is read, written and deleted as the user, while the backup in `%ProgramData%\MyTune`, state and logging stay admin, with bytes passed across. All game settings paths come from `LOCALAPPDATA`, `APPDATA` or HKCU Documents, none from the install folder, so no game file keeps admin rights; "under Program Files" would not be a safe rule anyway, because Steam's folder there grants Users Full Control. A file the user may not change fails the tweak with a clear message and keeps the backup. A game file that exists but cannot be read fails Save, shows a notice when the dialog opens, and counts as changed for Put back; only a truly missing file is skipped. `start2.bin.bak.path` records where the pins came from: a restore to any other path fails and keeps the backup, and a backup from an older version (no record) restores as before. Per-user variables (`LOCALAPPDATA`, `APPDATA`, `USERPROFILE`, temp) still pick these paths, and are used without the helper only in `voicenote.rs`, `settingspage.rs` and `startup.rs`.
- Apply safety (audit 2026-11-21, tested with fakes, never on a real failure): a failed first apply is undone, and its capture dropped; if the undo fails too, the backup stays, marked `PartlyApplied`, and the row shows a "Partly applied" chip. An automatic restore point is made once per run on the work thread before the first batch from a tweak page (`sysreport::restore_point_once`); the Internet page and the taskbar card's one-time carry-over call it too; PC check and Game Hub do not. When MyTune runs under another account than the shell, tweaks writing HKCU or the Start pin file are refused; revert stays allowed. Explorer restart from a tweak or the Tools button is scoped to this session and comes back unelevated; the button reports success only when a new shell window is up. The Mouse page's acceleration switch is refused under another account. The Tools stability log's "Switch off" reverts on a thread, one at a time, and its button shows "Switching off" meanwhile. `cust.clearstart` and `cust.outlineselect` read off at the next state read while their helper failed to load, and it keeps retrying.
- Game tweak safety (audit 2026-11-21, tested with fakes and headless shots, never applied or reverted on a real game): a config revert that cannot reach the file keeps its copy and record; Forget (Game Hub row of an uninstalled game, or Restore after a failed Undo of a settings file, never for GPU or NVIDIA entries) drops them after asking. A missing backup copy is always a failed Undo, even when the file changed. Copies are deleted only after the save. Revert all includes game tweaks and the PC check Game Mode fix (`pccheck.gamemode`, now through the Engine), and skips a running game. Undo asks before overwriting a file changed since apply. Game files are written by temp file and `ReplaceFileW`; read-only flag and modified time come back on revert. FPS caps and binds are never written, and absent keys (`sg.*`) are never added: such rows show "Not in this game's file". GPU preference edits only its own token and also targets the real Unreal binary beside a stub (`pergame::GpuTweak`; on when either path has it, so a stub set by an older version stays on; revert clears only the paths its backup records, so a token MyTune never wrote stays; not tested live). G-SYNC stores and restores its prior state; a backup from before this has none, so revert leaves G-SYNC as it is and says so. Old Defender, QoS and NVIDIA per-game backups revert through `pergame::revert_only`.
- Removed in 2.3.7 because they have no measurable benefit (don't re-add): MMCSS Games priority, Win32PrioritySeparation, power throttling off, global and per-game fullscreen optimizations off, per-game IFEO High priority, Avoid core 0, IRQ spread, dynamic tick, Nagle, NetworkThrottlingIndex, fastest DNS, TCP stack, services/SysMain/Search to Manual, fixed page file, memory compression off, every RAM/standby cleaner (auto, on game start, buttons, tray). `Catalog.Removed` keeps only what undoes them; `WhatsNew.RevertRemoved` reverts any still applied on the first window load and lists them in What's new.
- Background work must be near free while hidden or gaming: sensors read every 1 s only while the window is shown (not minimized) or a game runs, else every 5 s (`Sensors.Watched`); the Dashboard skips updates while hidden; the VPN keeper checks on network-address changes plus every 2 min; the Processes card samples only while visible; the game watcher takes one process list per 3 s tick.
- Power plan values come from HyperTune's embedded plans, recreated with powercfg (not by importing their .pow). NVIDIA settings use public DRS setting IDs. Exact HyperTune values for services/NIC keywords/game config edits were encrypted, so conservative well-known values are used; game config-file edits are not implemented.
- Power plan audit fixes (Rust app, 2026-11-21, `tweaks.rs`): cooling policy is Active on AC, the display keeps the base plan's AC timeout, laptops do not park cores on mains and use 5% minimum state on battery. Existing installs get these values only when the plan is applied again. Applying during a game takes over the booster's record of the user's plan. Checked with fake powercfg only; never applied on a real PC.
- Per-game CPU affinity (P-cores only) is applied by a watcher while MyTune runs in the tray; anti-cheat games refuse it ("Access is denied", logged once per process).
- Game booster (`Services/GameBooster.cs`, runs off GameService.RunningChanged): while any Game Hub game runs it holds a 0.5 ms timer (only if the Optimize > Advanced "adv.timer" tweak is on, which also sets GlobalTimerResolutionRequests=1), and optionally quiets toasts and switches to the performance plan. No app suspending. Optional background throttle (`Services/BackgroundThrottle.cs`, Settings toggle `ThrottleBackground`): browsers, launchers and updaters get below-normal priority (plus efficiency mode) while a game runs, restored on exit; nothing is suspended or closed, Steam/Discord/Riot client are never touched.
- `ServicesManualTweak` (with `Names`) is used by deb.xbox and deb.spooler. Scheduled-task tweaks use the Task Scheduler COM API, not schtasks text, so they work on non-English Windows.
- This PC has no `{current}` BCD entry; bcdedit calls fall back to `{default}`.
- `_disabled\` holds the old MyTune v1 (disabled exe, source, its backup file) and is excluded from the build.

## Releases
- Friends get MyTune through `installer\build.ps1` (Inno Setup, `installer\output\MyTune-rs-Setup-<version>.exe`). The `AppId` in `installer\MyTune-rs.iss` must never change, it is how a newer setup upgrades an older install in place.
- Setup bundles the PawnIO and ViGEmBus driver installers unmodified in `installer\redist\` (pinned in `SHA256SUMS.txt`; `build.ps1` fails if a hash or signature changes). They are offered as checkboxes on the last Setup page (PawnIO ticked, ViGEmBus not), skipped when already installed or during silent updates. Credits are in `installer\THIRD-PARTY-NOTICES.txt`.
- `forced-update` (only with the `license` feature; a dev build never checks): at start MyTune reads the signed `version.json` of the latest `castielcx/mytune-rs` release. A newer version blocks the whole window, licence screen included, with one **Update now** button. The daily check and Settings > Check now only offer it as a banner. A failed check (offline, bad feed) changes nothing and locks nobody out. The block never shows during a voice call or while a call rings: a running call turns it into a banner until the next start, a ring only holds it back until the ring ends. A failed update keeps the user locked, with Retry, Download manually and Revert all tweaks; there is no continue button (owner's decision, 2026-11-21). The Ed25519 signature covers version, URL and SHA-256. The URL must be exactly `<tag>/<asset>` after the release prefix, segments `[A-Za-z0-9._-]`. The setup is downloaded to `%ProgramFiles%\MyTune Updates` (resolved with `SHGetKnownFolderPath`; not ProgramData, where a standard user can pre-create and own a folder), hash-checked and run silently with `/RELAUNCH`. A setup that stops before finishing starts the app with `--update-failed`; uninstall deletes the folder. Code: `mytune-core/src/updater.rs`, `mytune-ui/src/updategate.rs`, `mytune-keys` (`update-keygen`, `update-sign`), `installer\MyTune-rs.iss`, `installer\build.ps1`. Release order: upload the setup and `version.json` to a draft, then publish it, so `/releases/latest/` never serves half a release. Until the owner's key step replaces the placeholder `UPDATE_PUBLIC_KEY`, a release build stops on purpose and no release can be made. Measured: unit tests only. Never tried: the full install with a real setup, relaunch, `--update-failed`, the uninstall delete, clicks on the screen in a real window.
- Publish a release with the two `gh release` commands `installer\build.ps1` prints at its end (draft first, then latest). `.claude\commands\release.md` still describes the deleted C# release: do not use it.

## Publishing
- Always publish (rebuild and restart the running app) once a task's other criteria are met (code done, checks passed), as soon as no other agent is working on the same thing (same files or feature). If another agent still is, wait or do other work, then publish; if it cannot happen, report the change as unpublished. After each publish try (refused, failed or waiting), try again automatically 40 seconds later, but only if no other agent is working on the same thing at that moment; if one is, skip that try and check again after 40 seconds. There is no publish queue (since 2026-11-21, mytune-agents mod): the publish is one PowerShell tool command, `& '<mytune-rs>\target\.agents\publish.ps1'` (script written by the mod; it stops MyTune, builds with the features and always starts it again; the mod never rewrites the command, because auto mode refuses a call a hook changed), with nothing chained to it, and a hand build of mytune-ui into `target\debug` or a stop of MyTune is refused; whoever asks while no publish runs goes, and an agent whose edits are already in another agent's good build is answered "already live" and is done. Self-check of the mod: `node test\sim.mts` in `~\.claude\mods\mytune-agents`.
